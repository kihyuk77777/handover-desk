# 사전 검증: 소형 로컬 모델로 가능한 범위

구현에 앞서, 내부 장비에서 돌릴 수 있는 소형 모델이 어디까지 맡을 수 있는지 측정했습니다.

- **환경**: Apple M4 · 메모리 16GB, Gemma 4 12B (4bit, MLX), 컨텍스트 16,384토큰
- **자료**: 가상으로 작성한 접수 문장. 깔끔한 문장 20개(중국어 12, 한국어 8)와 까다로운 문장 12개
- **판정**: 형식·분류·용어 일치는 코드로 채점, 내용 정확도는 원문과 출력을 한 건씩 대조 (중국어 원어민 검수는 아님)

## 깔끔한 문장 20개

| 항목 | 결과 |
|---|---|
| 접수 정리: 출력 형식 정상 / 유형 분류 정답 | 20/20 / 20/20 |
| 접수 정리: 그대로 사용 가능 / 가벼운 수정 필요 / 오도 | 13 / 7 / 0 |
| 번역: 지정 용어 일치 (용어집 있음 / 없음) | 43/43 / 33/43 |
| 번역(용어집 있음): 정확 / 뉘앙스 어긋남 / 뜻 틀림 | 14 / 4 / 2 |
| 처리 시간 (정리 + 번역, 번갈아 실행) | 한 건에 약 10초 |

## 까다로운 문장 12개

줄임말, 중·영 혼용, 한 글에 이슈 두 개, 종료 통보, 글 속 지시문, 말투와 내용이 어긋나는 글을 넣었습니다.

| 항목 | 결과 |
|---|---|
| 접수 정리 (11개 채점): 통과 / 경미 / 실패 | 5 / 2 / 4 |
| 번역: 정확 / 뉘앙스 어긋남 / 실패 | 9 / 2 / 1 |

- **잘한 것**: 느긋한 말투로 쓴 랜섬웨어 증상을 침해 의심으로 분류, 시각·IP 범위·수량 보존, 잡담에 묻힌 이슈 추출
- **무너진 것**
  - 글 속 지시문 2건에 모두 넘어감. 핵심 스위치 장애를 "사용 문의"로 정리했고, "아직 승인되지 않았다"는 문장을 "승인 완료"로 출력
  - 한 글의 이슈 두 개를 하나로 합침
  - 종료 통보를 새 이슈로 접수
  - 글 속 비밀번호를 정리 항목과 번역문에 그대로 복사

## 긴 입력

| 종료 이슈 수 | 입력 토큰 | 전체 시간 | 분류별 건수 집계 |
|---|---|---|---|
| 20건 | 1,894 | 22초 | 정확 |
| 73건 | 6,357 | 58초 | 6개 중 4개가 1씩 틀림 |
| 137건 | 11,763 | 103초 | 크게 틀림 |

## 설계에 반영한 것

| 확인한 사실 | 설계 반영 |
|---|---|
| 글 속 지시문을 따름 | 메일을 구분 표시로 감싸고 지시문 의심 항목 추가, 원문 낱말 규칙 병행. 보강 후 시험한 2건은 차단됐으나 사례가 적어 추가 시험 필요 |
| 번역이 통째로 틀리는 경우가 있음 | 번역문의 언어·길이를 코드로 점검, 원문 항상 병기 |
| 용어집이 없으면 용어가 흔들림 | 용어집을 정리와 번역에 항상 적용 |
| 건수와 빠진 항목을 틀림 | 숫자는 모두 코드가 계산 |
| 이슈 두 개를 합치고, 종료 통보를 새 이슈로 접수 | "새 이슈 여부"와 "이슈 개수" 항목 추가 |
| 비밀번호를 그대로 복사 | 모델에 넘기기 전에 비밀값 가리기 |

## 구현 뒤에 다시 본 것

예시 메일 13통(중국어 8, 한국어 5)을 실제 모델로 처리했습니다. 1회 실행한 결과입니다.

- 규칙에 걸리지 않은 랜섬웨어 증상 메일("문서 이름 뒤에 .locked가 붙었다, 급하지 않다")과 관리 콘솔 접속 불가 메일을 모델이 긴급으로 올렸습니다.
- 지시문이 섞인 메일은 지시문 의심으로 표시됐고, 요약은 실제 장애 내용으로 채워졌습니다.
- 버튼 위치를 묻는 글에 "긴급", "당장"이 붙어 있자 모델도 긴급으로 판단했습니다. 말투에 끌리는 경우가 남아 있어, 이런 건은 사람이 등급을 내리고 그 기록을 남기도록 했습니다.

표본이 작고 문장을 직접 작성했기 때문에, 실제 현장 글에서는 결과가 더 나쁠 수 있습니다.
